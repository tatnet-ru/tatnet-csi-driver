# tatnet-csi-driver

[tatnet.ru](https://tatnet.ru) · [панель](https://min.tatnet.ru) ·
[документация](https://docs.tatnet.ru) ·
[справочник API](https://api.tatnet.ru/v1/docs)

CSI-драйвер блочных томов TatNet для **managed Kubernetes**. Даёт PVC поверх
`volumes` платформы: LV на общем FC SAN региона, прикрепляемый к node-VM вторым
virtio-диском.

Форма повторяет [`tatnet-cloud-controller-manager`](https://github.com/tatnet-ru/tatnet-cloud-controller-manager):
проектный `tn_live_`-ключ, доставка в кластер inline-манифестом от
k8s-orchestrator, никакого прямого доступа к БД платформы.

## Объём (v1)

Есть: create / delete, attach / detach, **онлайн-расширение**, топология по
региону, RWO.

Нет: снапшотов (`VolumeSnapshot`) и RWX. RWX здесь не «не сделали», а
физически невозможно: это одно устройство с одной файловой системой, и двое
пишущих — порча ФС. Общий доступ требует NFS-сервера, то есть другого продукта.

## Два режима, и почему они разделены

| режим | что делает | креды |
|---|---|---|
| `controller` | говорит с `/v1`: создаёт, удаляет, прикрепляет, открепляет, растит | ключ проекта |
| `node` | находит устройство по серийнику, форматирует, монтирует | **нет** |

Node-плагин крутится DaemonSet'ом на КАЖДОЙ ноде, включая те, куда попадает
клиентская нагрузка. Ключ проекта там означал бы, что он лежит на каждой машине
клиента.

## Как том находится на ноде

Единственная связь между идентификатором тома в платформе и устройством в
госте — **серийник** virtio-диска (`volumes.device_serial`, 20 символов —
предел, который udev кладёт в by-id). Контроллер передаёт его в
`volume_context`, node-плагин ищет:

1. `/dev/disk/by-id/virtio-<serial>` — как все облачные CSI; симлинк
   появляется вскоре после горячего подключения, поэтому поиск повторяется;
2. запасной путь — обход `/sys/block/*/serial`, не зависящий ни от чего, кроме
   ядра: by-id существует ровно постольку, поскольку в системе жив udev с
   нужными правилами.

Не нашли — ошибка. Угадывать по порядку появления или по размеру драйвер не
будет: примонтировать «похожее» устройство хуже, чем не примонтировать ничего.

Идентификатор машины node-плагин читает из `/var/lib/tatnet/vm-id` — файла,
который k8s-orchestrator кладёт в машинный конфиг ноды. Не запрос к платформе
(кредов нет) и не имя ноды Kubernetes (другая система имён, меняется
независимо).

## ⚠ Отключение диска не спрашивает гостя

У virtio-blk нет договора об извлечении: живое отключение диска со
**смонтированной** файловой системой проходит успешно, устройство исчезает из
`/sys/block`, и гость об этом не предупреждают. Отказать в таком отключении
гипервизор не может — спросить некого.

Поэтому платформа отказывает в откреплении работающей машины без явного флага,
а драйвер этот флаг ставит — как **свидетельство**, а не как «сломай»:
Kubernetes зовёт `NodeUnstageVolume` до `ControllerUnpublishVolume`, то есть к
моменту отключения ФС размонтирована этим же драйвером.

## Сборка

```
go build ./... && go test ./...
docker build -t <registry>/tatnet-csi-driver:<tag> .
```

Образ не distroless намеренно: node-плагину нужны `mkfs.ext4`/`xfs` и
`resize2fs`/`xfs_growfs` — `mount-utils` зовёт их как внешние программы, и без
них драйвер поднимается, а падает на первом же PVC.
